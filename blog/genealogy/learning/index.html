The genealogy of language models

August 11, 2026

How do models actually learn?

In the previous section, we built the model and hopefully grounded our intuition to understand the choices made and raison d'être. However, it should be abundantly clear that there is no information regarding how they learn nor why they learn. The matrices WQ,WK,WVW^Q,W^K,W^VWQ,WK,WV do not begin knowing what a noun is. The embedding for dog is not "close" to the embedding for puppy. No attention head has been assigned the job of resolving pronouns. The feed-forward networks contain no handwritten rules of grammar.

Surprisingly, the motivation for the model to learn is essentially

predict the correct token.

For the original transformer, the one created for translation, we add some specificity:

given the source sentence and the correct target prefix, predict the next target token.

Everything else follows from repeatedly measuring how wrong the model was and changing its parameters so that, next time, the correct token receives slightly more probability, and thus more likely to be chosen. However, before we begin this discussion, it is worth backtracking and clarifying a particular term.

Tokens

We mentioned previously that the model takes an input sequence of symbol representations xxx. xxx is not the words that compose the sentence, but instead integers produced by a tokenizer that converts text into a sequence drawn from some finite vocabulary

V={1,…,V}.\mathcal{V} = \{1, \ldots, V\}.V={1,…,V}.

Using our example sentence

"The transformer unpacks unhelpful words into smaller pieces before processing them."

the GPT-5.x Tokenizer splits it into 15 tokens, namely

The transformer unpacks unhelpful words into smaller pieces before processing them.

whose corresponding token IDs are

[976,59595,537,103878,537,11283,1500,6391,1511,13679,12762,2254,12323,1373,13].[976, 59595, 537, 103878, 537, 11283, 1500, 6391, 1511, 13679, 12762, 2254, 12323, 1373, 13].[976,59595,537,103878,537,11283,1500,6391,1511,13679,12762,2254,12323,1373,13].

The number of tokens does not match the number of words found nor the number of characters found; tokens are sub-word.

Why sub-word?

Language is considered to be open vocabulary in that it is not restricted to a predefined set of words or phrases; names, compounds, spelling variations, technical terminology, and newly invented words make it impossible to maintain a reasonably sized vocabulary containing every word one might encounter. Tokenizing every character is untenable as the sequences simply become too long.

Sennrich, Haddow, and BirchCitationSenntich et al. Neural Machine Translation of Rare Words with Subword Units ARXIV had shown that byte-pair encoding could be adapted to neural machine translation by decomposing uncommon words into reusable sub-word units. A frequent word might remain a single token; a rare word might become several smaller tokens. This provided a fixed vocabulary without requiring every possible word to have its own entry.

A larger vocabulary allows more strings to be represented with a single token, shortening sequences, but requires larger embedding and output matrices. A smaller vocabulary reduces those matrices but produces longer sequences. And because ordinary self-attention scales quadratically with sequence length, tokenization ultimately affects far more than vocabulary size.

Tokenization will eventually become an engineering problem of its own. For now, assume that some tokenizer has handed us a sequence of token IDs.

Weight Tying

In what we have described above, it seems to follow that we would have one embedding matrix

E∈RV×dmodelE \in \mathbb{R}^{V \times d_{\text{model}}}E∈RV×dmodel​

that maps tokens to vectors, and an "output" matrix

Wout∈RV×dmodelW_{\text{out}} \in \mathbb{R}^{V \times d_{\text{model}}}Wout​∈RV×dmodel​

that maps hidden vectors against possible output tokens.

However, I ask you to reframe this. The row EvE_vEv​ asks, in effect

what vector should represent token vvv when I read it?

while (Wout)v(W_{\text{out}})_v(Wout​)v​ asks

what direction in representation space should make me believe the answer is token vvv?

Press and WolfCitationPress and Wolf showed that the output matrix of a neural language model itself behaves as a meaningful word embedding, and found that tying the input and output matrices could improve language-model perplexity while substantially reducing parameter count. In neural translation models, their experiments found that weight tying could reduce model size dramatically without degrading performance. Inan, Khosravi, and Socher independently arrived at closely related weight-sharing results from a loss-based analysis.CitationInan, Khosravi, and Socher

We therefore impose

Wout=E.W_{\text{out}} = E.Wout​=E.

With our convention that vocabulary embeddings occupy the rows of EEE, logits become

ℓt=Eht.\ell_t = Eh_t.ℓt​=Eht​.

The original Transformer take weight tying one step further: it shares the weight matrix between both embedding layers and the pre-softmax output transformation; this commonly called three-way weight tying.

Weight tying reduces capacity in exchange for parameter efficiency and an inductive bias that says these two problems ought to share structure. With that being said, there is no mathematical necessity that the best space for interpreting an input token must be identical to the best space for classifying an output token.

We can now read symbols, transform them, and convert the final representations into probabilities.

We still need to define what counts as being wrong.

The objective

We are still basking in the sun of 2017, and so the ensuing discussion about training is not what we do with modern day large language models but instead focused on translation.

Let x=⟨x1,…,xn⟩x = \langle x_1, \ldots, x_n \ranglex=⟨x1​,…,xn​⟩ be the source sentence and y=⟨y1,…,ym⟩y = \langle y_1, \ldots, y_m \rangley=⟨y1​,…,ym​⟩ be the target translation. Our goal is to for the model to assign a high probability to the entire correct translation: pθ(y∣x)p_\theta(y \mid x)pθ​(y∣x).

Using one of our earlier remarks, the probability assigned to an entire translation is equivalently the product of the probabilities assigned to each correct next token:

p(y∣x)=p(y1∣x)⋅p(y2∣y1,x)⋅p(y3∣y2,y1,x)⋅… .p(y \mid x) = p(y_1 \mid x) \cdot p(y_2 \mid y_1, x) \cdot p(y_3 \mid y_2, y_1, x) \cdot \dots.p(y∣x)=p(y1​∣x)⋅p(y2​∣y1​,x)⋅p(y3​∣y2​,y1​,x)⋅….

The product of many small probabilities is numerically awkward and requires a high level of floating point precision, so we log both sides:

log⁡pθ(y∣x)=∏t=0m−1log⁡pθ ⁣(yt+1∣y≤t,x).\log p_\theta(y \mid x) = \prod_{t=0}^{m-1} \log p_\theta\!\left(y_{t+1} \mid y_{\leq t}, x\right).logpθ​(y∣x)=t=0∏m−1​logpθ​(yt+1​∣y≤t​,x).

Cross-entropy

Suppose the correct next token is yyy. Let qqq be its one-hot target distribution:

Causal shifting

Suppose our desired target sequence is y1,y2,y3,y4y_1, y_2, y_3, y_4y1​,y2​,y3​,y4​. To train

p(y3∣y2,y1,x),p(y_3 \mid y_2,y_1,x),p(y3​∣y2​,y1​,x),

Teacher forcing

There is a vital choice made in our discussion so far, that is worth explicitly pointing out now: teacher forcing. That is, using the true value rather than the network's own previous output, and feeding it back into the subsequent computation during training. Spelling it out with an example, suppose the target begins

The transformer unpacks...

When learning to predict unpacks, we condition the model on the correct prefix

The transformer

regardless of whether the model itself would actually have predicted transformer one step earlier.

Teacher forcing combines particularly well with causal masking: since every correct previous token is known, the entire shifted target can enter the decoder at once.

A sentence containing mmm target tokens therefore gives us roughly mmm supervised next-token prediction problems in one forward pass. This is one of the reasons the deceptively simple next-token objective scales so effectively.

Training & Inference

What happens when we are no longer training? More precisely, during training, when predicting token ttt, irrespective of what the model picked earlier, it receives y<ty_{< t}y<t​, the correct prefix. But during inferenceDefinitionInference is the process of using an already trained large language model to generate text or answers for new user prompts. the model receives y^<t\hat y_{< t}y^​<t​, its own generated prefix, one that could be incorrect.

This train-test mismatch became known as exposure bias. Bengio et al.CitationBengio et al. proposed scheduled sampling: gradually replace some ground-truth previous tokens during training with tokens generated by the model itself, thereby exposing the model to the kinds of prefixes it will encounter at inference.

Huszár subsequently showed that the scheduled-sampling objective is not, in general, a consistent estimator of the data distribution: the apparent fix can alter what distribution the model is incentivized to learn.CitationHuszár

RemarkA subtle but important point

It is common to say "teacher forcing causes exposure bias, therefore maximum likelihood is flawed."

The autoregressive factorization is exact. If every learned conditional matched the true conditional distribution, sampling autoregressively from the model would reproduce the correct joint distribution.

The practical problem is that our learned conditionals are imperfect. During rollout, an imperfect prediction may place us in regions of sequence space where those approximations are worse, allowing errors to compound.

So there is a genuine train-generation mismatch, but simply replacing maximum likelihood with model-generated prefixes does not automatically solve it.

This issue will return much later under other names and other training paradigms.

How does loss reach attention heads?

Going back to our example sentence from the previous section, "Because the trophy was too large for the suitcase, it did not fit.", suppose one of our attention heads eventually learns that it should retrieve information from trophy. How does it learn about this mistake? Backpropagation.

Backpropagation conveys the fact that some later layer realizes that the model assigned an insufficient probability mass to the correct translated token, by carrying the errors backwards through the computation graph.

Consider a single attention operation written as Z=AVZ = AVZ=AV, where

A=softmax⁡(QK⊤dk).A = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right).A=softmax(dk​​QK⊤​).

Suppose the gradient arriving from later layers is

G=∂L∂Z,G = \frac{\partial \mathcal{L}}{\partial Z},G=∂Z∂L​,

then using the definition of ZZZ, the gradient with respect to the values VVV is

∂L∂V=A⊤G.\frac{\partial \mathcal L}{\partial V} = A^\top G.∂V∂L​=A⊤G.

The forward attention weights therefore also influence where learning signal is routed backward through the value pathway. Similarly,

∂L∂A=GV⊤.\frac{\partial \mathcal L}{\partial A} = GV^\top.∂A∂L​=GV⊤.

That error propagates backward through the softmax and then through QK⊤QK^\topQK⊤, producing gradients for both QQQ and KKK and ultimately for WQW^QWQ, WKW^KWK, and WVW^VWV. Since those matrices were themselves produced from previous hidden representations, the gradient continues backward through every preceding Transformer block, all the way to the embeddings.

The process therefore looks something like

  1. At each target position, the model produces a probability distribution over the vocabulary. The loss compares this distribution with the correct next token and measures how much probability the model failed to assign to the desired answer.
  2. For softmax with cross-entropy, this begins with the signal ∂L∂ℓj=pj−qj\frac{\partial \mathcal L}{\partial \ell_j}=p_j-q_j∂ℓj​∂L​=pj​−qj​. The correct token receives a negative gradient when its probability is too low, while incorrect tokens receive positive gradients proportional to how much probability the model assigned them.
  3. Since the logits are produced from the final decoder representation, ℓt=Woutht\ell_t=W_{\text{out}}h_tℓt​=Wout​ht​, the logit gradients determine how the final hidden state hth_tht​ should have changed to make the correct token more probable. If the output weights are tied to the embedding matrix, this step also contributes directly to the gradient of that shared matrix.
  4. The gradient flows backward through the feed-forward network, residual connections, layer normalization, and cross-attention and masked self-attention sublayers. Each operation receives a signal describing how changing its output would have changed the final loss.
  5. For an attention operation, gradients flow both through the retrieved information VVV and through the attention weights AAA. Thus the model can learn both what information should be carried and where it should have retrieved that information from.
  6. The gradients through AAA propagate through the softmax and the score matrix QK⊤QK^\topQK⊤, producing gradients for QQQ and KKK. Together with the gradient through VVV, these ultimately produce gradients for WQW^QWQ, WKW^KWK, and WVW^VWV.
  7. Because QQQ, KKK, and VVV were constructed from hidden representations produced by previous layers, the gradient does not stop at a single attention head. It propagates recursively through earlier attention blocks and feed-forward networks, assigning credit or blame to every computation that contributed to the prediction.
  8. Eventually the gradient arrives at the representations with which the computation began. The embedding vectors for tokens that appeared in the example are adjusted according to how changes in those vectors would have affected the final prediction. Over many examples, tokens whose representations are useful in similar contexts can consequently acquire related structure.
  9. After backpropagation, the model has a gradient ∇θL\nabla_\theta\mathcal L∇θ​L describing, locally, how the loss would change if each parameter were perturbed. This includes the embedding matrix, attention projections, feed-forward weights, normalization parameters, and output projection.
  10. Backpropagation tells us the direction in which each parameter affects the loss; it does not by itself decide how large an update to make. An optimizer takes these gradients and converts them into parameter updates. In the original Transformer, that optimizer was Adam, together with a carefully chosen learning-rate schedule.

Given all of these gradients, how should we actually update the model?

How does it improve?

Training uses minibatches. Sequences in a batch generally need compatible tensor shapes, so shorter sequences are padded.

The paper describes batch size in tokens, not merely number of sentences. A batch of 100 ten-token sequences has very different computational cost from a batch of 100 thousand-token sequences.

For each minibatch we obtain a scalar loss L(θ)\mathcal L(\theta)L(θ), differentiate it

gt=∇thetaL(θt),g_t = \nabla_theta \mathcal L(\theta_t),gt​=∇t​hetaL(θt​),

and then need to decide how far to move the parameters. Naively,

θt+1=θt−ηgt,\theta_{t+1} = \theta_t - \eta g_t,θt+1​=θt​−ηgt​,

which is gradient descent. The transfomer uses something far more intricate: Adam.CitationKingma and Ba. Adam A Method for Stochastic Optimization

Suppose one parameter repeatedly receives gradients like {0.0001,0.0002,0.0002,…}\{0.0001, 0.0002, 0.0002, \ldots \}{0.0001,0.0002,0.0002,…} while another receives {8,−1,4,…}\{8, -1, 4, \ldots \}{8,−1,4,…}. Using exactly the same effective update scale for both can make optimization difficult. Adam (adaptive moment estimation) maintains running statistics for every parameter.

Given gradient, gtg_tgt​, Adam first tracks an exponential moving average of the gradient:

mt=β1mt−1+(1−β1)gt.m_t = \beta_1m_{t-1} + (1-\beta_1)g_t.mt​=β1​mt−1​+(1−β1​)gt​.

This is an estimate of its first moment. Informally, mtm_tmt​ behaves somewhat like momentum: it smooths the noisy minibatch gradient and preserves information about its recent direction. Adam also maintains an exponential moving average of the squared gradient:

vt=β2vt−1+(1−β2)gt2.v_t = \beta_2v_{t-1} + (1-\beta_2)g_t^2.vt​=β2​vt−1​+(1−β2​)gt2​.

This estimates the second raw moment. Parameters whose gradients have historically been large therefore accumulate larger vtv_tvt​.

Because both moving averages begin at zero, early estimates are biased toward zero. Adam corrects this:

m^t=mt1−β1tv^t=vt1−β2t.\hat m_t = \frac{m_t}{1-\beta_1^t} \qquad \hat v_t = \frac{v_t}{1-\beta_2^t}.m^t​=1−β1t​mt​​v^t​=1−β2t​vt​​.

θt=θt−1−ηtm^tv^t+ϵ.\theta_t = \theta_{t-1} - \eta_t \frac{\hat m_t}{\sqrt{\hat v_t} + \epsilon}.θt​=θt−1​−ηt​v^t​​+ϵm^t​​.
